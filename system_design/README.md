## The RESHADED Framework

Use this for every design:

1. **R**equirements: What are we building?
2. **E**stimations: How big? How fast?
3. **S**torage: Data model and database choice
4. **H**igh-level design: Major components
5. **A**PI design: How components communicate
6. **D**etailed design: Deep dive on key parts
7. **E**valuate: Trade-offs and bottlenecks
8. **D**istinctive: What makes this unique?

## Tips for Success

1. **Draw everything**: Diagrams clarify thinking
2. **Practice estimation**: Numbers matter in interviews
3. **Know trade-offs**: There's no perfect solution
4. **Talk out loud**: Practice explaining your designs
5. **Review weekly**: Reinforce concepts

## FAQ

**Q: Do I need to memorize all systems?**
A: No. Understand patterns and apply them to new problems.

**Q: How detailed should designs be?**
A: Cover high-level architecture + deep dive on 1-2 components.

**Q: What if I can't finish in 60 minutes?**
A: Focus on quality. Return to finish later if needed.

**Q: Should I code these designs?**
A: Not required for interviews, but implementing helps understanding.
